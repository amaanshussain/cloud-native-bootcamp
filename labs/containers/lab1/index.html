Containers Lab¶

40 min Beginner

In this lab you'll build a container image for a small web service, run it, inspect it, and push it to a public registry.

This lab uses a tutorial reference format. Each step gives you a goal and points to the section of the Container Tool Tutorials or Registry Tutorials that shows the command you need. You build the command yourself by adapting the tutorial's example to this lab. When the tutorials don't cover something, the step gives you the command and explains what it does.

Keep the tutorials open

Open the Container Tool Tutorials in a second tab before you start. Its Podman and Docker tabs show the same commands for both engines. This lab uses quay.io/podman/hello and greeting where the tutorial uses nginx and my-web-app, and it listens on port 8080 inside the container where the tutorial's NGINX uses port 80.

Prerequisites¶

  • A container engine:
    • Podman (recommended). On macOS and Windows, run podman machine init and podman machine start once after installing.
    • Docker also works. Every podman command in this lab works the same with docker.
  • A terminal and a text editor.
  • A free Quay.io account, used to push your image in Part 4.

Part 1: Verify your setup¶

  1. Find out which version of your container engine is installed.

    • Reference: Container Tool Tutorials, step 1
    • Check: the output shows a client version.

  2. Run the quay.io/podman/hello container. The container should be deleted automatically when it exits.

    • Reference: Container Tool Tutorials, step 3 shows how to run a container. It doesn't cover deleting a container on exit, so add this flag: --rm
    • Check: you see Hello Podman World, and podman ps -a doesn't list the container.

  3. List the images stored on your machine.

    • Reference: Container Tool Tutorials, step 2
    • Check: quay.io/podman/hello is in the list, and it's less than 1 MB.

Part 2: Build an image¶

Create the application¶

Create a directory named greeting and move into it:

mkdir greeting && cd greeting

Save the following two files in it. The service returns a JSON greeting and reads its message from the GREETING environment variable.

main.go
// greeting is the sample service used throughout the Cloud Native Bootcamp labs.
//
// Endpoints:
//
//  /greeting?name=<name>[&delay_ms=<n>]  JSON greeting; delay_ms adds latency (max 5000)
//  /fail                                  always returns HTTP 500 (for alerting exercises)
//  /healthz                               liveness/readiness check
//  /metrics                               Prometheus metrics
//
// Configuration (environment variables):
//
//  GREETING                     message returned by /greeting
//  OTEL_EXPORTER_OTLP_ENDPOINT  enables OpenTelemetry tracing when set, e.g. http://collector:4318
//  OTEL_SERVICE_NAME            service name reported in traces (default "greeting")
package main

import (
    "context"
    "encoding/json"
    "errors"
    "log/slog"
    "net/http"
    "os"
    "os/signal"
    "strconv"
    "syscall"
    "time"

    "github.com/prometheus/client_golang/prometheus"
    "github.com/prometheus/client_golang/prometheus/promauto"
    "github.com/prometheus/client_golang/prometheus/promhttp"
    "go.opentelemetry.io/contrib/instrumentation/net/http/otelhttp"
    "go.opentelemetry.io/otel"
    "go.opentelemetry.io/otel/attribute"
    "go.opentelemetry.io/otel/exporters/otlp/otlptrace/otlptracehttp"
    "go.opentelemetry.io/otel/propagation"
    "go.opentelemetry.io/otel/sdk/resource"
    sdktrace "go.opentelemetry.io/otel/sdk/trace"
    "go.opentelemetry.io/otel/trace"
)

var (
    logger = slog.New(slog.NewJSONHandler(os.Stdout, nil))
    tracer = otel.Tracer("greeting")

    requests = promauto.NewCounterVec(prometheus.CounterOpts{
        Name: "greeting_requests_total",
        Help: "HTTP requests handled, by path and status code.",
    }, []string{"path", "code"})
    duration = promauto.NewHistogramVec(prometheus.HistogramOpts{
        Name:    "greeting_request_duration_seconds",
        Help:    "HTTP request latency in seconds, by path.",
        Buckets: prometheus.DefBuckets,
    }, []string{"path"})
)

func main() {
    ctx, stop := signal.NotifyContext(context.Background(), syscall.SIGINT, syscall.SIGTERM)
    defer stop()

    shutdownTracing := setupTracing(ctx)
    defer shutdownTracing()

    message := os.Getenv("GREETING")
    if message == "" {
        message = "Welcome to the Cloud Native Bootcamp!"
    }

    mux := http.NewServeMux()
    mux.Handle("/greeting", instrument("/greeting", greetingHandler(message)))
    mux.Handle("/fail", instrument("/fail", func(w http.ResponseWriter, r *http.Request) {
        writeJSON(w, http.StatusInternalServerError, map[string]string{"error": "simulated failure"})
    }))
    mux.HandleFunc("/healthz", func(w http.ResponseWriter, r *http.Request) {
        w.Write([]byte("ok"))
    })
    mux.Handle("/metrics", promhttp.Handler())

    server := &http.Server{Addr: ":8080", Handler: mux, ReadHeaderTimeout: 10 * time.Second}
    go func() {
        logger.Info("greeting service listening", "addr", server.Addr)
        if err := server.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
            logger.Error("server failed", "error", err)
            os.Exit(1)
        }
    }()

    <-ctx.Done()
    logger.Info("shutting down")
    shutdownCtx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
    defer cancel()
    server.Shutdown(shutdownCtx)
}

func greetingHandler(message string) http.HandlerFunc {
    return func(w http.ResponseWriter, r *http.Request) {
        name := r.URL.Query().Get("name")
        if name == "" {
            name = "World"
        }
        if ms, err := strconv.Atoi(r.URL.Query().Get("delay_ms")); err == nil && ms > 0 {
            slowDown(r.Context(), min(ms, 5000))
        }
        _, span := tracer.Start(r.Context(), "compose greeting")
        span.SetAttributes(attribute.String("greeting.name", name))
        body := map[string]string{"message": message, "name": name}
        span.End()
        writeJSON(w, http.StatusOK, body)
    }
}

// slowDown simulates a slow dependency, recorded as its own span.
func slowDown(ctx context.Context, ms int) {
    _, span := tracer.Start(ctx, "slow dependency")
    defer span.End()
    span.SetAttributes(attribute.Int("delay_ms", ms))
    time.Sleep(time.Duration(ms) * time.Millisecond)
}

// instrument records Prometheus metrics, a trace span and a structured log line per request.
func instrument(path string, next http.HandlerFunc) http.Handler {
    handler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        start := time.Now()
        rec := &statusRecorder{ResponseWriter: w, code: http.StatusOK}
        next(rec, r)
        elapsed := time.Since(start)

        requests.WithLabelValues(path, strconv.Itoa(rec.code)).Inc()
        duration.WithLabelValues(path).Observe(elapsed.Seconds())

        attrs := []any{"method", r.Method, "path", path, "code", rec.code, "duration_ms", elapsed.Milliseconds()}
        if sc := trace.SpanContextFromContext(r.Context()); sc.IsValid() {
            attrs = append(attrs, "trace_id", sc.TraceID().String())
        }
        logger.InfoContext(r.Context(), "request", attrs...)
    })
    return otelhttp.NewHandler(handler, path)
}

type statusRecorder struct {
    http.ResponseWriter
    code int
}

func (r *statusRecorder) WriteHeader(code int) {
    r.code = code
    r.ResponseWriter.WriteHeader(code)
}

func writeJSON(w http.ResponseWriter, code int, body any) {
    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(code)
    json.NewEncoder(w).Encode(body)
}

// setupTracing sends traces over OTLP/HTTP when OTEL_EXPORTER_OTLP_ENDPOINT is set.
// Without it, tracing stays a no-op and the service runs as before.
func setupTracing(ctx context.Context) func() {
    if os.Getenv("OTEL_EXPORTER_OTLP_ENDPOINT") == "" {
        return func() {}
    }
    if os.Getenv("OTEL_SERVICE_NAME") == "" {
        os.Setenv("OTEL_SERVICE_NAME", "greeting")
    }
    exporter, err := otlptracehttp.New(ctx)
    if err != nil {
        logger.Error("tracing disabled: cannot create OTLP exporter", "error", err)
        return func() {}
    }
    res, _ := resource.New(ctx, resource.WithFromEnv(), resource.WithTelemetrySDK())
    provider := sdktrace.NewTracerProvider(sdktrace.WithBatcher(exporter), sdktrace.WithResource(res))
    otel.SetTracerProvider(provider)
    otel.SetTextMapPropagator(propagation.NewCompositeTextMapPropagator(propagation.TraceContext{}, propagation.Baggage{}))
    tracer = otel.Tracer("greeting")
    logger.Info("tracing enabled", "endpoint", os.Getenv("OTEL_EXPORTER_OTLP_ENDPOINT"))

    return func() {
        ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
        defer cancel()
        provider.Shutdown(ctx)
    }
}

You don't need Go installed. The build happens inside a container.

Write the Containerfile¶

A Containerfile describes how to build the image. Save this file as Containerfile in the same directory:

Containerfile
# Stage 1: compile the Go binary with Red Hat's Go toolchain image
FROM registry.access.redhat.com/ubi9/go-toolset AS builder
COPY --chown=1001:0 go.mod go.sum ./
RUN go mod download
COPY --chown=1001:0 . .
RUN CGO_ENABLED=0 go build -o greeting .

# Stage 2: copy only the binary into a minimal runtime image
FROM registry.access.redhat.com/ubi9/ubi-micro
COPY --from=builder /opt/app-root/src/greeting /usr/local/bin/greeting
EXPOSE 8080
USER 1001
CMD ["greeting"]

Container Tool Tutorials, step 6 explains FROM, COPY and EXPOSE. It doesn't cover multi-stage builds, RUN, USER or CMD:

  • AS builder names the first stage so a later stage can copy files from it.
  • COPY --from=builder copies from an earlier stage instead of from your directory.
  • RUN runs a command at build time. Here it compiles the Go program into a single binary.
  • USER 1001 runs the app as a non-root user. OpenShift ignores this and assigns a random UID, which is why the app doesn't depend on a particular user.
  • CMD is the command that runs when the container starts.

This is a multi-stage build. The first stage contains the whole Go toolchain, which is over 1 GB. The final image contains only the compiled binary on top of ubi-micro, so it's around 30 MB. Smaller images pull faster, start faster, and have fewer packages that could contain vulnerabilities.

Build it¶

  1. Build the image from the current directory and tag it greeting:v1.0.0.

    • Reference: Container Tool Tutorials, step 7
    • Check: the build ends with Successfully tagged localhost/greeting:v1.0.0.

  2. List your images and compare the size of greeting with the size of go-toolset.

    • Reference: Container Tool Tutorials, step 2
    • Check: greeting is around 30 MB, and go-toolset is over 1 GB. Why is there such a difference?

Part 3: Run and inspect the container¶

Port already in use?

If something else on your machine uses port 8080, map a different host port, for example -p 9080:8080, and use that port in the steps below.

  1. Run the image in the background, name the container greeting, and make the service reachable on port 8080 of your machine.

    • Reference: Container Tool Tutorials, step 3. The flag table explains -d, --name and -p. Use the image name localhost/greeting:v1.0.0 with Podman, and the container listens on port 8080.
    • Check: the command prints a container ID and returns your prompt.

  2. Call the /greeting endpoint with the name John using curl.

    • Reference: Container Tool Tutorials, step 3 shows curl. The path is /greeting and the query parameter is name.
    • Check: the response is JSON containing "name":"John".

  3. Try to start a second container with the same name greeting, on host port 8081.

    • Reference: Container Tool Tutorials, step 3
    • Check: it fails. Read the error and explain why.

  4. List the running containers.

    • Reference: Container Tool Tutorials, step 4
    • Check: greeting is listed with its port mapping.

  5. Look at the container's full configuration. Then print only its status and IP address.

    • Reference: Container Tool Tutorials, step 4 shows the full configuration. It doesn't cover printing selected fields, so use this command:
    podman inspect greeting --format '{{.State.Status}} {{.NetworkSettings.IPAddress}}'
    Part What it does
    podman inspect greeting Prints the container's configuration as JSON
    --format '...' Takes a Go template. Each {{ }} selects one field from the JSON
    Expected output
    running 10.88.0.2
    • Check: the output is a single line such as running 10.88.0.2.

  6. Show the container's logs.

    • Reference: Container Tool Tutorials, step 4
    • Check: you see greeting service listening on :8080.

  7. Run a command inside the running container to find out which user the app runs as. The command that prints the current user is id.

    • Reference: Container Tool Tutorials, step 4. The tutorial opens a shell. Run id directly instead of /bin/sh, and leave out -it.
    • Check: the output shows UID 1001.

  8. Stop and remove the container. Start a new one with the same name and port, but change the greeting message by setting the GREETING environment variable. Call it again.

    • Reference: Container Tool Tutorials, step 5 covers stopping and removing. It doesn't cover environment variables, so add this flag to your run command: -e GREETING="Hello from my container"
    • Check: the message in the response is your custom text.

Part 4: Push the image to a registry¶

A container registry stores and distributes images. Docker Hub, Quay.io and GitHub Container Registry are public registries. OpenShift also has a built-in internal registry.

  1. Log in to Quay.io.

    • Reference: Registry Tutorials, Red Hat Quay tab, step 1
    • Check: you see Login Succeeded!

    Single sign-on?

    If your Quay account uses single sign-on (for example, a Red Hat login), create an encrypted password under Account Settings > Docker CLI Password and use it to log in instead of your account password.

  2. Give your image a second name that points to your Quay repository: quay.io/<your-username>/greeting:v1.0.0.

    • Reference: Registry Tutorials, Red Hat Quay tab, step 2
    • Check: greeting:v1.0.0 and your Quay name appear in the image list with the same image ID.

  3. Push the image to Quay.

    • Reference: Registry Tutorials, Red Hat Quay tab, step 3
    • Check: the push finishes with Writing manifest to image destination.

  4. On quay.io, open the new greeting repository and, under Settings, make it public. New repositories are private by default.

    • Check: the repository shows a Public badge.

  5. Remove all local copies of the greeting image (and the container), then pull the image back from Quay.

    • Reference: Container Tool Tutorials, step 5 shows how to remove a container. Step 10 shows how to remove images, and step 2 shows how to pull.
    • Check: the pull succeeds without asking you to log in.

Building on Apple Silicon (M-series Macs)?

Images you build on an ARM Mac are arm64 by default, but most OpenShift clusters run on amd64 (x86_64) nodes. Pods fail there with exec format error. The tutorials don't cover building for another platform, so use one of these:

# Single platform
podman build --platform linux/amd64 -t quay.io/<your-username>/greeting:v1.0.0 .

# Multi-arch manifest list for amd64 and arm64
podman build --platform linux/amd64,linux/arm64 --manifest quay.io/<your-username>/greeting:v1.0.0 .
podman manifest push quay.io/<your-username>/greeting:v1.0.0
Part What it does
--platform linux/amd64 Builds the image for x86_64 nodes instead of your machine's CPU architecture
--platform linux/amd64,linux/arm64 Builds one image per platform
--manifest <name> Groups those images into a manifest list, so a pull picks the image that matches the node's architecture
podman manifest push Pushes the manifest list and every image in it

Cleanup¶

Remove the greeting container and the local greeting:v1.0.0 image.

  • Reference: Container Tool Tutorials, step 10

Keep the greeting image on Quay. The Image Registry Lab deploys it to OpenShift.
